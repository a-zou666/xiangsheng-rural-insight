# 《乡声——乡村文化 AI 导览创作助手》作品说明

- 主推类别：AIGC 类数字创意作品创作赛项（AIGC 智能助手与交互体验）
- 关联主题：数字文化传播 / 乡村振兴·农文旅融合
- 作品形态：纯软件 / 算法 / 数据（无硬件）
- 运行方式：本地离线运行，浏览器访问；语音播报用浏览器内置能力

---

## 一、选题背景与价值

乡村文化、非遗与农文旅现场常缺少**适合不同年龄与语言背景、能快速获取且可信**的讲解：纸质导览牌信息有限、讲解员稀缺、通用大模型易「一本正经地编造」地方历史。本作品把问题限定为「为到访游客 / 研学学生提供可信、分龄、可听的本地文化讲解」，而非笼统宣称「AI 助力乡村振兴」。

当前版本以示例村落「青溪村·竹编技艺与古村文化」搭建可运行闭环，用于演示**可信资料组织、带引用问答、拒答机制与多模态交互**的方法与工程完成度。作品**尚未进行真实用户访谈或当地场馆验证**，不主张已落地；资料均为团队按公开资料风格整理的示例内容，待实地核验。

---

## 二、作品概述

「乡声」把团队整理并标注来源的本地文化资料，组织成**可观测、可测试、确定性可复现**的检索增强问答流水线：

```
问题 → ①检索(BM25) → ②充分性判定(拒答) → ③带编号引用答案组装
                                     ↘ 可选 LLM 接地改写(需显式配置, 失败回退规则)
资料 → 分龄/研学/双语【讲解改写】(保留事实, 原文对照)
点位/路线 → 【导览叙事脚本】→ 浏览器 Web Speech API 语音播报(离线)
```

### 核心功能

1. **检索增强可信问答（带引用）**：中文提问先经纯 Python 手写 BM25（中文单字 + 相邻二元切分）检索本地资料，再确定性地组装带编号引用的答案。每条引用给出来源名称、来源类型与人工审核状态，可追溯、可核验。

2. **「资料不足」拒答（抗幻觉）**：采用确定性双阈值——绝对相关度下限 `MIN_TOP_SCORE=5.0` 与按 IDF 加权的主题覆盖率下限 `MIN_ANSWERABILITY=0.43`。两者任一不达标即回答「资料不足」，并给出命中/缺失主题词与判定阈值，不编造历史事实。为避免中文跨词边界产生的「垃圾二元」误伤覆盖率，判定前用已知词锚定字符、剔除边界噪声。

3. **分龄 / 研学 / 双语讲解改写**：对任一资料条目生成「儿童版 / 普通版 / 研学版 / English」讲解，**保留事实不变**，界面同时展示 AI 改写文本与原始资料对照，并标注「AI 改写，事实以原文为准」。

4. **离线语音导览**：按导览路线逐站生成讲解词，前端用浏览器 **Web Speech API**（`SpeechSynthesisUtterance`，`lang=zh-CN`）朗读，无需联网或外部模型，是「音频导览」的离线可运行替代。

5. **点位与路线浏览**：提供村落点位卡片（含关联资料标题与引用）与有序慢行导览路线（步行时长、慢行提示）。

6. **人工审核台**：汇总每条资料的来源类型、审核状态、审核人备注与版本记录，突出**人机协同**而非无人审核生成。

7. **可复现评估面板**：对示例问题集（应作答 20 题 / 应拒答 12 题）离线确定性地计算作答准确率、引用命中率、拒答正确率、关键词事实匹配率与响应时间。**该问题集为团队设计的示例测试集，不代表真实用户测试。**

### 可插拔 AI 增强（可选）
默认问答为确定性检索 + 规则组装。显式配置 OpenAI 兼容接口后，可用外部 LLM 做「接地改写」，提示词要求模型**只依据给定资料、保留 [n] 引用、资料不足则说明**；调用失败自动回退规则组装。模型不是作品核心创新，数值与事实仍以本地资料为准。

### 遗留模块（不属于本产品体验）
旧「县域数据分析看板」（熵权法-TOPSIS 指数、地图、洞察、问数、预测，`/dashboard.html`）为遗留辅助模块，使用虚构合成数据、不支持真实县域结论；本次产品化已将其从主页面移除入口链接，相关文件暂予保留仅供参考，不作为作品主舞台。

## 三、技术实现与规范

- **技术栈**：后端 Python 3 标准库（`http.server`、`json`、`csv`、`dataclasses`，**不使用 numpy/pandas，不依赖 pip 安装任何包**）；前端原生 HTML/CSS/JavaScript；检索（BM25）、分词、充分性判定、讲解模板全部手写实现；语音用浏览器 Web Speech API；产品页用纯 CSS/SVG 自绘视觉系统（遗留看板图表用本地离线 ECharts）。
- **架构**：知识库层（`data/culture_kb.json` 带来源/审核/版本）→ 加载层（`backend/kb.py`）→ 检索层（`backend/retrieval.py` BM25）→ AI 核心（`backend/guide.py`：问答/拒答/改写/叙事）→ 评估层（`backend/evaluation.py`）→ 服务层（`backend/server.py` HTTP API）→ 展示层（`web/index.html` + `web/guide.js` + `web/app.css`，单一游览流程、首屏即产品）。模块职责单一、低耦合。
- **可信约束**：回答与检索片段绑定；每条可作答结果给出编号引用；资料不足明确拒答；改写只做风格/语言转换、事实以原文为准并标注 AI 改写；外部模型仅在显式配置后用于接地改写且被约束只依据给定资料。
- **工程规范**：关键函数含类型注解与中文文档字符串；检索与判定确定性、可复现；提供 `tests/smoke_test.py` 覆盖知识库加载、BM25 检索、带引用问答与拒答、分龄/研学/双语改写、导览叙事、服务层导览 API 与评估面板，并保留辅助看板测试；一键核验，全通过退出码为 0；提供 Windows / Linux-macOS 一键启动脚本；服务默认仅监听本机回环地址。
- **可验证性**：评审可在无网络环境下 `python backend/server.py` 启动，浏览器访问即用；`python tests/smoke_test.py` 一键复核。

## 四、创新性与原创贡献

1. **可信资料组织 + 带引用问答 + 拒答机制的工程闭环**：把「检索—充分性判定—带引用组装—拒答」做成可观测、可测试、确定性可复现的流水线，针对通用大模型「编造地方历史」的痛点给出可审计的替代方案。
2. **去噪的中文充分性判定**：用已知词锚定字符、剔除跨词边界「垃圾二元」，再按 IDF 加权计算主题覆盖率，减少对「域外提问」的误判与对真实问题的误拒。
3. **保留事实的分龄 / 双语讲解与原文对照**：改写只做风格/语言转换并与原文并列展示，体现「AI 改写、人核事实」的协同。
4. **离线可运行的多模态体验**：Web Speech API 语音导览 + 点位路线浏览，默认零联网、零外部模型。
5. **透明的人工审核台与可复现评估**：来源/审核/版本可查，评估指标可一键复算并如实标注为示例测试集。
6. 熵权法、TOPSIS、BM25 等均为**成熟通用方法的手写实现**，不主张算法原创；创新在资料组织、拒答、交互与评估设计及团队资料采写核验。

## 五、完成度与运行验证

- 功能闭环完整：知识库 / 检索 / 带引用问答 / 拒答 / 分龄双语改写 / 语音导览 / 点位路线 / 审核台 / 评估面板全部实现并打通；遗留数据看板文件保留但已从产品移除入口链接。
- 端到端冒烟测试结果：以 `python tests/smoke_test.py` 实际输出为准（含导览与数据看板两部分）。
- 零第三方运行时依赖、默认离线可运行、跨平台一键启动，评审可独立复现。

## 六、应用与推广

- **目标验证对象（尚未访谈）**：乡村/非遗点位的到访游客、亲子研学学生，以及场馆/村镇内容负责人；不宣称已验证其需求。
- **后续验证路径**：取得当地可公开/可授权资料与口径确认 → 扩充并人工审核资料库 → 组织 ≥5 名目标用户完成「找到点位—提问—阅读/收听有来源讲解」任务并记录成功率与满意度 → 与纯模型自由生成做对照，确认带检索与拒答版本更可信。
- **可扩展**：知识库为 JSON 驱动，新增条目/点位/路线即可被检索与导览识别；可插拔 LLM 支持面向更复杂开放式问答升级；可增量接入图像识别等多模态能力。
